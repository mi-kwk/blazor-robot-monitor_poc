# 課題 1：電池が少なくなったら充電場へ行き、満タンまで充電する

学習者（私）が自分で取り組む、最初の改修の課題です。答えのコードは書いていません。

## 背景（動作確認で気づいたこと）

模擬ロボットをしばらく動かすと、多くのロボットの電池残量が下がり続け、「電池残量の低下」の異常が次々に出ます。

今の模擬ロボット（`src/RobotMonitor.Simulator/SimRobot.cs`）では、

- 待機中は 1 秒に 1.0% 充電される
- 移動中は 1 秒に 0.5%、作業中は 0.3% 減る
- 待機は 2〜5 秒と短く、すぐに次の移動を始める

ため、減る量のほうが多くなっています。現実のロボットのように、**電池が少なくなったら自分で充電場へ行く**動きを作ります。

## ゴール（できたと判断する条件）

1. 倉庫の決まった場所に「充電場」がある
2. 電池残量が決めた値（例：30%）を下回ったロボットは、今の仕事の区切りで充電場へ向かう
3. 充電場に着いたら充電し、満タン（100%）になったら、また普通に動き出す
4. 普通に動かしている限り、「電池残量の低下」の異常が出なくなる（`b N` で無理に減らしたときは出てよい）
5. 画面で「充電中」のロボットが分かり、地図に充電場が表示される（段階 2）

## 進め方（3 段階）

### 段階 1：模擬ロボットだけを直す（C# だけ。Blazor は使わない）

触るファイル：`src/RobotMonitor.Simulator/SimRobot.cs`（必要なら `src/RobotMonitor.Shared/Thresholds.cs`）

- 画面は直さずに、今ある状態（待機・移動中・作業中）だけで充電の動きを作ります。たとえば「充電場へ向かう間は移動中、充電中は待機」とします。
- 確かめ方：模擬ロボットのターミナルで `list` を入力し、電池が少ないロボットが充電場の位置へ行き、電池が増えていくことを見る。

### 段階 2：「充電中」を画面に出す（ここで Blazor を触る）

触るファイル：

| ファイル | 直すこと（例） |
| --- | --- |
| `src/RobotMonitor.Shared/Models.cs` | ロボットの状態に「充電中」を足し、表示用の日本語名も足す |
| `src/RobotMonitor.Server/wwwroot/app.css` | 「充電中」の色を決める |
| `src/RobotMonitor.Client/Pages/Map.razor` | 充電場のマスを色付けして表示する |
| `src/RobotMonitor.Simulator/SimRobot.cs` | 充電中は「充電中」を報告する |

- 型を `Shared` にまとめているので、状態を 1 つ足すと、模擬ロボット・サーバー・画面の 3 つに同じ型が届きます。C# で統一している利点を確かめられます。
- 一覧画面の状態の絞り込み（`Home.razor`）は、状態の一覧から自動で選択肢を作っているので、直さなくても「充電中」が選べるようになるはずです。本当にそうなるか確かめてください。

### 段階 3（余裕があれば）

- 充電場が埋まっていたら、空くまで待つ（順番待ち）
- 電池が少なすぎて充電場まで届かないロボットをどうするか
- 一覧の上部の台数に「充電中 ○ 台」が出ることを確かめる

## 自分で決めること

| 決めること | 考える点 |
| --- | --- |
| 充電場の場所と数 | 例：左上の角に 2 マス。地図の大きさは `Thresholds.GridWidth` / `GridHeight` |
| 充電に向かう電池残量 | 異常の値（20%）より上にしないと、充電に向かう前に異常が出る |
| いつ充電に向かうか | 待機中だけ？ 移動中や作業中なら、終わってから？ |
| 充電の速さ | 1 秒に何 % 増やすか。速すぎると確かめにくく、遅すぎると全台が充電場に集まる |
| 値をどこに書くか | 模擬ロボットの中か、`Thresholds.cs` か |

決めたことと理由は `docs/判断ログ.md` の「A. 利用者が判断したこと」に書きます。

## ヒント（答えではありません）

- `SimRobot` の動きは `Step()` → `StepNormal()` の `switch (State)` で決まっています。まずここを読んで、待機 → 移動中 → 作業中 → 待機の流れを紙に書いてみると分かりやすいです。
- 行き先は `_target` に入っています。充電場へ向かうときは、行き先を充電場にすればよさそうです。
- ただし、移動中のロボットが「着いたら作業中になる」作りなので、「充電場に着いたときは作業ではなく充電にする」には、**今どこへ向かっているのか**を覚えておく必要があります。
- 今の待機中の充電（`Battery += 1.0`）を残すか、充電場でだけ充電するように変えるかも、自分で決めます。
